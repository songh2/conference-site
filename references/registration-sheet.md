# 홈페이지 안 등록 양식 + 구글 시트 (Apps Script) 설정 안내

홈페이지의 "등록" 칸에서 참석 희망자가 **이름 · 소속 기관 · 참석 구분 · 이메일**을 직접 입력하면,
내용이 **구글 시트에 한 줄씩 쌓이는** 기능이다. 구글폼 링크를 따로 열 필요가 없다.

```
참석 희망자 ── 홈페이지의 등록 양식 ──▶ Apps Script(작은 접수 프로그램) ──▶ 구글 시트 ('등록' 탭)
                                                  │
홈페이지의 '참가자 명단' ◀── 이름·소속만(명단 게시 동의자만) ──┘   (이메일은 밖으로 나가지 않음)
```

- 홈페이지는 정적 파일이라 서버가 없다. 그래서 **구글 Apps Script** 가 서버 역할을 한다(무료, 구글 계정만 있으면 됨).
- 시트 주인(= 이 스크립트를 만든 계정)만 응답 전체를 볼 수 있다. 홈페이지 방문자는 이름·소속(동의자만)만 볼 수 있다.

## 한눈에 보는 순서 (처음 한 번, 20~30분)

| 단계 | 하는 일 | 누가 |
|:---:|---|---|
| 1 | 구글 시트 새로 만들기 | 담당자 |
| 2 | Apps Script 열고 코드 붙여 넣기 | 담당자 |
| 3 | `setup` 실행 (권한 허용) | 담당자 |
| 4 | 웹 앱으로 배포하고 주소 복사 | 담당자 |
| 5 | 주소를 `registration.endpoint` 에 넣고 다시 빌드·배포 | 담당자 또는 AI 도우미 |
| 6 | 홈페이지에서 시험 등록 → 시트 확인 → 시험 줄 삭제 | 담당자 |

> 화면 문구·메뉴 위치는 구글이 바꾸면 조금 달라질 수 있다. 아래는 일반적인 예시다.

## 0. 먼저 정할 것

> 계정 선택(개인/학교/부서 공용)과 인수인계는 `docs/manual-google-sheet.md` 에 자세히 있다.

- **어느 구글 계정으로 만들 것인가?** 시트와 스크립트는 만든 계정에 묶인다. 행사 후에도 몇 년씩 유지해야 하고 담당자가 바뀔 수 있으므로
  **학교 계정이나 부서 공용 계정**을 권장한다. 개인 계정으로 만들었다면 나중에 "공유 → 소유권 이전"이 필요하다.
  (학교 구글 워크스페이스의 정책에 따라 외부 공개용 웹 앱 배포가 제한될 수 있다. 이 점은 학교 설정을 직접 확인해야 하며 이 문서로는 확인하지 못했다.)
- **개인정보 수집·이용 안내문**(`registration.privacy_notice`)의 보유 기간 등 문구를 학과·교수님·학교 개인정보 담당 부서에서 확정한다.
  이 스킬이 만든 문구는 **초안**이다.

## 1. 구글 시트 만들기

1. 구글 드라이브(drive.google.com) → **새로 만들기 → Google 스프레드시트**
2. 왼쪽 위 "제목 없는 스프레드시트"를 눌러 이름을 바꾼다. 예: `<행사명> 사전등록`

## 2. Apps Script 열고 코드 붙여 넣기

1. 시트 메뉴 **확장 프로그램 → Apps Script** (새 탭이 열린다)
2. 코드 편집 창에 `function myFunction() {}` 같은 기본 코드가 있다. **전부 선택(Ctrl+A / Cmd+A)해서 지운다.**
3. 이 저장소의 `sites/<slug>/registration-sheet.gs` 파일을 열어 **내용 전체를 복사해 붙여 넣는다.**
   (파일이 없거나 설정을 바꿨다면 `python3 scripts/make_registration_script.py sites/<slug>` 로 다시 만든다. AI 도우미에게 "등록 스크립트 다시 만들어 줘"라고 해도 된다.)
4. 위쪽 디스크 모양(**프로젝트 저장**, Ctrl+S)을 누르고, 왼쪽 위 "제목 없는 프로젝트"는 `<행사명> 접수`처럼 바꿔 둔다.

## 3. setup 실행 (권한 허용)

1. 편집기 위쪽 함수 선택 칸(▶ 실행 옆의 드롭다운)에서 **`setup`** 을 고른다.
2. **▶ 실행** 을 누른다.
3. "승인 필요" 창이 뜨면 **권한 검토** → 계정 선택.
4. "Google에서 확인하지 않은 앱" 경고가 나올 수 있다. 직접 만든 스크립트라서 나오는 안내이며,
   **고급 → (프로젝트 이름)(안전하지 않음)으로 이동 → 허용** 을 누른다. 이 스크립트가 요청하는 것은 스프레드시트 보기·수정 권한이다. 코드가 시트를 주소(ID)로 여는 방식(`openById`)을 쓰므로, 권한 화면에는 "스프레드시트 파일 전체"처럼 넓게 표시될 수 있다(정확한 문구는 구글이 정하며 이번에 확인하지 못했다). 시트를 만드는 전용 계정으로 진행하면 영향 범위가 작다.
5. 아래 "실행 로그"에 `setup 완료` 가 나오면 성공. 시트로 돌아가면 **`등록`**, **`집계`** 두 탭이 생겨 있다.

## 4. 웹 앱으로 배포하기

1. Apps Script 오른쪽 위 **배포 → 새 배포**
2. "유형 선택" 옆 톱니바퀴 → **웹 앱**
3. 설정:
   - 설명: `접수 v1`
   - **다음 사용자로 실행: 나** (스크립트가 내 계정 권한으로 시트에 기록)
   - **액세스 권한이 있는 사용자: 모든 사용자 (Anyone)** — 홈페이지 방문자는 구글 로그인이 없으므로 반드시 이 항목이어야 한다.
4. **배포** → 나타나는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사해 둔다.
5. 확인: 그 주소를 새 브라우저 탭에 붙여 넣으면 `{"ok":true,"service":"conference-registration", ...,"open":true}` 같은 글이 보여야 한다.
   (구글 로그인 화면이 나오거나 오류가 나면 3번의 "모든 사용자" 설정을 확인한다.)

## 5. 홈페이지에 연결하기

1. `sites/<slug>/conference.json` 의 `registration.endpoint` 에 복사한 주소를 붙여 넣는다.
   ```json
   "registration": {
     "endpoint": "https://script.google.com/macros/s/AKfy.../exec",
     "attendance_options": [ ... ],
     "privacy_notice": { "ko": "...", "en": "..." }
   }
   ```
2. 검사·빌드·배포
   ```bash
   python3 scripts/validate.py sites/<slug>/conference.json
   python3 scripts/build.py sites/<slug> --deploy dist/<slug>
   ```
   그 뒤 `dist/<slug>/` 내용을 공개 저장소(GitHub Pages)에 올린다. → `references/hosting.md`
   (이미 배포된 저장소의 `conference.json` 만 GitHub 웹에서 고쳐도 된다. `index.html` 안의 사본보다 이 파일을 먼저 읽는다.)
3. 이 단계는 AI 도우미에게 "웹 앱 주소는 ○○○ 이야, ntc2027 에 연결하고 배포 저장소에 반영해 줘"라고 요청해도 된다.

## 6. 시험 등록

1. 홈페이지 "등록" 칸에서 본인 이름·이메일로 등록해 본다. 성공하면 초록색 "등록이 접수되었습니다." 상자가 나온다.
2. 구글 시트 `등록` 탭 맨 아래에 한 줄이 생겼는지 확인한다. `집계` 탭의 숫자도 바뀐다.
3. 명단 게시 동의를 체크했다면 "참가자 명단"에 이름·소속이 나타난다(캐시 때문에 1분 정도 걸릴 수 있다).
4. 시험 줄은 `등록` 탭에서 **행 번호를 우클릭 → 행 삭제** 한다.

## 받는 항목과 시트 열 구성

| 열 | 내용 |
|---|---|
| A 접수시각 | 서버 기록 시각(한국 시간) |
| B 성명 / C 소속 / D 이메일 | 방문자가 입력한 값 (이메일은 소문자로 저장) |
| E 참석구분코드 / F 참석구분 | `conference.json` 의 `attendance_options` 의 `id` 와 한글 라벨 |
| G… 날짜별 열 | 참석하는 날에 `Y` (예: 2027-02-10, 2027-02-11, 2027-02-12) — 날짜별 인원·식사·명찰 준비에 쓴다 |
| 명단게시동의 | `Y` = 홈페이지 참가자 명단에 이름·소속 게시에 동의 |
| 개인정보동의 | 항상 `Y` (미동의면 접수되지 않음) |
| 언어 | 방문자가 보던 화면 언어 (ko/en) |
| 상태(관리용) | 담당자가 직접 입력. **`취소`** 로 바꾸면 집계·명단에서 빠진다 (`확인완료` 는 표시용) |
| 비고(관리용) | 같은 이메일로 다른 참석 구분을 다시 접수하면 자동으로 "같은 이메일로 이전 접수 있음(○행)" 이 적힌다 |

### 참석 구분 바꾸기
`conference.json` 의 `registration.attendance_options` 를 고친 뒤, 스크립트를 다시 만들고(`make_registration_script.py`)
Apps Script 편집기의 코드를 **통째로 교체**하고 `setup` 을 다시 실행한다(기존 등록 줄은 지워지지 않지만 날짜 열 구성이 바뀌면 열이 어긋나므로, 접수가 시작된 뒤에는 되도록 바꾸지 않는다).
코드를 바꾼 뒤에는 **배포 → 배포 관리 → (연필) 편집 → 버전: 새 버전 → 배포** 를 해야 같은 주소에 반영된다(주소는 그대로 유지된다).

## 운영하면서 알아 둘 것

- **마감**: `집계` 탭의 `B1` 칸을 `마감` 으로 바꾸면 즉시 접수가 중단된다(코드 재배포 불필요). 홈페이지는 `registration.deadline` 이 지나면 양식을 "마감" 문구로 바꾼다. 서버 쪽 마감일도 쓰려면 `deadline` 을 넣고 스크립트를 다시 만들어 반영한다.
- **중복**: 같은 이메일 + 같은 참석 구분은 한 번만 기록된다. 같은 이메일로 다른 참석 구분을 보내면 새 줄이 추가되고 비고에 표시된다. 참가자 명단은 같은 이메일의 **가장 최근 줄**을 기준으로 한다. 이전 줄은 상태에 `취소` 를 적어 정리한다.
- **수정·취소 요청**: 방문자가 직접 고칠 수는 없다. 시트에서 담당자가 고치거나 `취소` 처리한다. (확인 메일도 자동 발송하지 않는다.)
- **참가자 명단 갱신**: 따로 할 일이 없다. 홈페이지가 열릴 때 서버에 물어 최신 명단을 보여 준다(약 1분 캐시). `participants` 에 손으로 적은 명단은 서버 응답이 오면 그 응답으로 교체된다.
- **집계**: `집계` 탭에 총 접수 건수, 고유 이메일 수, 명단 게시 동의 수, 날짜별 인원, 참석 구분별 인원이 수식으로 계산된다. 식사·행사 준비 인원은 날짜별 인원을 쓴다.
- **스팸 방지**: 눈에 안 보이는 입력칸(자동 입력 프로그램 탐지)과 너무 빠른 제출 거부, 길이 제한, 수식 문자 제거, 접수 상한(기본 3000줄)이 들어 있다. 완벽한 방어는 아니다. 의심스러운 줄은 `취소` 로 표시한다.
- **개인정보 주의**
  - 시트는 **공유하지 않는다.** 필요한 사람에게만 "뷰어"로 공유하고, "웹에 게시"는 절대 켜지 않는다.
  - 등록 내용은 요청 주소(URL)의 일부로 구글 서버에 전달된다(HTTPS 암호화 구간). 일반적으로 방문자 브라우저의 방문 기록(주소창)에는 남지 않지만, 개인정보 처리 방침 작성 시 "구글 서버를 이용해 수집·보관"한다는 점을 학교 개인정보 담당 부서와 확인한다.
  - 행사 후 보유 기간이 지나면 시트의 개인정보 열을 삭제하거나 시트를 지운다(`privacy_notice` 에 적은 기간과 맞출 것).

## 문제 해결

| 증상 | 원인·해결 |
|---|---|
| 제출하면 "서버에 연결하지 못했습니다" | 웹 앱 주소 오타(`/exec` 로 끝나야 함), 배포 "액세스 권한"이 "모든 사용자"가 아님, 학교 네트워크·광고 차단 프로그램이 `script.google.com` 을 막음. 4단계 5번처럼 주소를 브라우저에 직접 열어 `{"ok":true…}` 가 나오는지 본다 |
| 주소를 열면 구글 로그인 화면 | 액세스 권한이 "모든 사용자"가 아님 → 배포 관리에서 수정 후 새 버전 |
| "등록을 접수하지 못했습니다" | Apps Script 편집기 왼쪽 **실행 기록**에서 오류 확인. `setup` 을 실행하지 않았거나 `등록` 탭 이름을 바꿨을 가능성 |
| 시트에 줄이 안 생김 | 같은 이메일+같은 참석 구분의 중복 접수, 또는 접수 상태가 `마감`(`집계!B1`), 또는 `deadline` 이 지남 |
| 참가자 명단에 안 나옴 | 명단 게시에 동의하지 않았거나 상태가 `취소`. 캐시 1분 대기 |
| 코드를 고쳤는데 그대로 | 새 버전 배포 필요 (위 "참석 구분 바꾸기" 참고) |
| 구글폼으로 대신하고 싶다 | `endpoint` 를 비우고 `form_url` 만 넣으면 이전 방식(링크/삽입)으로 돌아간다. `endpoint` 와 `form_url` 을 둘 다 넣으면 양식 아래에 "작동하지 않으면 구글 폼으로" 링크가 붙는다 |

## 확인된 것과 확인하지 못한 것

- 확인함(구글 공식 문서): `doGet`/`doPost` 로 웹 앱이 요청을 받는 방식, `배포 → 새 배포 → 웹 앱`, "다음 사용자로 실행: 나", 콘텐츠 서비스의 JSON 응답과 브라우저에서 `<script>` 로 읽는 방식(JSONP), 배포 버전을 바꿔도 주소가 유지됨.
- 테스트함(이 스킬 개발 중): 구글 서비스를 흉내 낸 모의 환경에서 접수·중복·마감·명단·수식 문자 제거 등 서버 로직, 실제 브라우저(Chromium)에서 양식 입력·검증·제출·언어 전환·모바일 화면.
- **확인하지 못함**: 실제 구글 계정에서의 종단 시험(권한 동의 화면 문구, "모든 사용자" 배포가 학교 워크스페이스에서 허용되는지, 일일 사용 한도). **6단계 시험 등록으로 반드시 확인한다.**
