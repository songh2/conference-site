# 등록 양식용 구글 계정·시트 준비 — 누구의 계정으로 만들 것인가

> 홈페이지의 "등록" 칸에서 참석자가 직접 입력한 내용은 **구글 시트**에 쌓이고, 그 사이에서 **구글 Apps Script**(작은 접수 프로그램)가 서버 노릇을 합니다. 둘 다 "만든 구글 계정"에 묶입니다.
> 이 문서는 **어느 계정으로 만들지**와 **담당자가 바뀔 때 어떻게 넘기는지**를 다룹니다. 시트·스크립트를 만드는 클릭 순서 자체는 `references/registration-sheet.md` 에 있습니다(초보자용으로 쓰여 있습니다).

## 1. 왜 계정 선택이 중요한가

- 시트에는 참석자의 **이름·소속·이메일**(개인정보)이 쌓입니다. 개인 계정에 두면 "개인이 개인정보를 보관"하는 모양이 됩니다.
- 접수 프로그램(웹 앱)은 **배포한 계정의 권한으로** 실행됩니다. 그 계정이 사라지거나 비밀번호를 잃으면 등록이 멈춥니다.
- 행사 후에도 참가자 명단은 시트에서 읽어 오므로, 시트가 살아 있어야 홈페이지 명단이 보입니다.
- 담당자(조교·행정직원)는 바뀝니다. 처음부터 **넘기기 쉬운 계정**으로 만들어야 합니다.

## 2. 세 가지 선택지

| | (A) 담당자 개인 구글 계정 | (B) 학교 Google Workspace 계정 (예: `@snu.ac.kr` 구글 계정이 있는 경우) | (C) 부서 공용 구글 계정 (새로 만든 Gmail) |
|---|---|---|---|
| 만들기 | 바로 가능 | 학교가 제공하는 경우만 | 10분 |
| 개인정보 보관 주체 | 개인 | 기관 | 기관(부서) |
| 담당자 교체 | 소유권 이전 필요(번거로움) | 계정이 사람에 묶이면 역시 이전 필요. 부서 공용 Workspace 계정이 있으면 가장 좋음 | 비밀번호·2단계 인증만 넘기면 됨 |
| 외부 공개 웹 앱 배포 ("모든 사용자" 접근) | 가능 | **학교 관리자 설정에 따라 막혀 있을 수 있음** — 확인 필요 (이 문서로는 확인하지 못했습니다) | 가능 |
| 권장 용도 | 시험·연습 | 학교가 공용 계정을 내주고 외부 배포가 허용되면 1순위 | 일반적인 1순위 |

**권장**: 학교 Workspace 에 **부서 공용 계정**을 만들 수 있고 외부 공개 웹 앱 배포가 허용되면 (B), 아니면 (C). (A)는 시험용으로만 쓰고, 실제 접수를 시작하기 전에 (B) 또는 (C)로 옮깁니다.

> 공용 계정 운영(비밀번호 공유 등)은 기관의 정보보안 규정을 따릅니다. 이 문서는 기술적 절차만 다루며, 규정 해석은 기관 담당 부서에 확인하세요.

## 3. (C) 부서 공용 구글 계정 만들기

1. 로그아웃된 브라우저(또는 시크릿 창)에서 https://accounts.google.com → **계정 만들기**.
2. 용도 선택 화면이 나오면 **본인 계정**(개인용)을 고릅니다. "업무용" 을 고르면 유료 Google Workspace 가입 안내로 이어질 수 있습니다. (문구는 구글이 바꿀 수 있습니다.)
3. 이름: 성에 부서, 이름에 역할을 넣습니다. 예) 성 `수리과학부`, 이름 `행사접수`. 홈페이지 방문자에게 보이지 않지만, 시트 공유 화면 등에 표시되므로 알아보기 쉽게 합니다.
4. 이메일 주소: `math-events@example.org` 처럼(지메일이면 `@gmail.com`) **부서를 알 수 있는 이름**으로. 이 주소가 접수 서버의 "소유자"가 됩니다.
5. 전화번호 인증을 요구하면 담당자 번호로 진행하고, 가입 후 **복구 전화·복구 이메일**을 부서 공용 메일로 바꿉니다(계정 → 보안).
6. **2단계 인증**을 켭니다. 인증 수단은 담당자 휴대폰 + **백업 코드**(인쇄해 부서 서류함 보관). 담당자가 바뀌면 새 담당자 휴대폰을 추가하고 이전 것을 지웁니다.
7. 비밀번호는 부서의 비밀번호 보관 규칙(밀봉 보관, 비밀번호 관리 프로그램 등)에 따릅니다. 메신저·메일로 보내지 않습니다.

## 4. 시트와 접수 프로그램 만들기 (공용 계정으로 로그인한 상태에서)

`references/registration-sheet.md` 의 1~6단계를 그대로 따릅니다. 요약:

| 단계 | 하는 일 | 걸리는 시간 |
|:---:|---|---|
| 1 | 구글 시트 새로 만들기 (이름 예: `<행사명> 사전등록`) | 1분 |
| 2 | 시트 메뉴 **확장 프로그램 → Apps Script** → 기본 코드 지우고 `sites/<slug>/registration-sheet.gs` 내용 붙여 넣기 → 저장 | 3분 |
| 3 | 함수 `setup` 선택 → **실행** → 권한 허용 ("확인하지 않은 앱" 경고는 직접 만든 코드라 나오는 것 → 고급 → 이동 → 허용) | 3분 |
| 4 | **배포 → 새 배포 → 웹 앱** → "다음 사용자로 실행: **나**", "액세스 권한: **모든 사용자**" → 배포 → 나온 주소(`…/exec`) 복사 | 3분 |
| 5 | 그 주소를 `conference.json` 의 `registration.endpoint` 에 넣고 홈페이지에 반영 (AI 도우미에게 "이 주소를 등록 양식에 연결해 줘") | 5분 |
| 6 | 홈페이지에서 **본인 이름으로 시험 등록** → 시트에 줄 생김 확인 → 시험 줄 삭제 | 3분 |

`registration-sheet.gs` 파일은 AI 도우미가 만들어 줍니다(`python3 scripts/make_registration_script.py sites/<slug>`). 참석 구분(어느 날 참석하는지 선택지)을 바꾸면 이 파일을 다시 만들어 Apps Script 코드를 통째로 교체하고 **새 버전으로 재배포**해야 합니다(주소는 유지됨).

## 5. 시트 운영 규칙 (개인정보)

- 시트는 **공유하지 않습니다.** 꼭 필요한 사람(교수님·담당자)에게만 "뷰어"로 공유합니다. **"웹에 게시"는 절대 켜지 않습니다.**
- 홈페이지의 참가자 명단은 접수 프로그램이 **명단 게시에 동의한 사람의 이름·소속만** 돌려주므로, 시트를 공개할 필요가 전혀 없습니다. 이메일은 밖으로 나가지 않습니다.
- 접수 마감: 시트의 `집계` 탭 **B1 칸을 `마감`** 으로 바꾸면 즉시 멈춥니다(재배포 불필요).
- 취소·수정 요청은 담당자가 시트에서 처리합니다(`상태` 열에 `취소`).
- 행사가 끝나고 안내문(`privacy_notice`)에 적은 보유 기간이 지나면 **시트의 개인정보 열을 지우거나 시트를 삭제**합니다. 명단을 홈페이지에 남기려면 그 전에 이름·소속만 `conference.json` 의 `participants` 로 옮깁니다(`docs/manual-github-pages.md` 10절).
- 등록 내용은 HTTPS 로 암호화되어 구글 서버에 저장됩니다. 개인정보 안내문에 "Google 시트에 저장"을 적고 국외 이전·위탁 고지가 필요한지는 **기관 개인정보 담당 부서**에 확인합니다. 이 저장소의 안내문은 초안입니다(법률 자문 아님).

## 6. 이미 개인 계정으로 만들었다면 — 공용 계정으로 옮기기

가장 확실한 방법은 **공용 계정에서 새로 만드는 것**입니다(4절, 20분). 접수가 시작되기 전이라면 이 방법을 쓰세요.

1. 공용 계정으로 4절 1~4단계를 새로 합니다 → **새 주소**(`…/exec`)가 나옵니다.
2. `conference.json` 의 `registration.endpoint` 를 새 주소로 바꿉니다(GitHub 웹에서 직접 고쳐도 됨).
3. 홈페이지에서 시험 등록으로 새 시트에 들어오는지 확인합니다.
4. 이전 개인 계정의 시트는 시험 자료를 지운 뒤 삭제하고, Apps Script 의 **배포 관리**에서 이전 배포를 **보관 처리(Archive)** 합니다(옛 주소로 들어오는 요청을 막기 위해).

접수가 이미 진행 중이라 기존 응답을 옮겨야 한다면:
1. 위처럼 공용 계정에 새 시트·배포를 만들고 홈페이지를 새 주소로 바꿉니다.
2. 기존 시트의 `등록` 탭 내용을 복사해 새 시트의 `등록` 탭에 붙여 넣습니다(머리글 제외, 열 순서가 같은지 확인).
3. 이후 기존 시트를 삭제합니다.

> 구글 드라이브의 "소유권 이전" 기능으로 시트를 넘길 수도 있지만, 웹 앱 배포는 **배포한 계정**에 묶여 있어 새 계정에서 **다시 배포**해야 하며(주소가 바뀜), 학교 Workspace 계정 ↔ 일반 Gmail 사이의 이전은 관리자 설정으로 막혀 있을 수 있습니다. 어느 쪽이든 결국 새 배포가 필요하므로 "새로 만들기"가 더 단순합니다. (소유권 이전 후 기존 배포가 어떻게 동작하는지는 이 문서로 확인하지 못했습니다.)

## 7. 인수인계 점검표

- [ ] 공용 계정의 비밀번호·2단계 인증 수단·백업 코드를 새 담당자에게 규정대로 전달
- [ ] 복구 전화번호를 새 담당자 번호로 변경, 이전 담당자 번호 삭제
- [ ] 시트 공유 목록에서 떠나는 사람 제거
- [ ] 홈페이지 저장소(GitHub) 권한도 같이 정리 (`docs/manual-github-pages.md` 9절)
- [ ] 시트 주소, 웹 앱 주소, 홈페이지 주소를 인수인계 서류에 기록

## 8. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 홈페이지에서 "서버에 연결하지 못했습니다" | 웹 앱 주소가 `/exec` 로 끝나는지, 배포의 "액세스 권한"이 **모든 사용자**인지, 학교 네트워크·광고 차단 프로그램이 `script.google.com` 을 막는지. 주소를 브라우저에 직접 열면 `{"ok":true,…}` 가 보여야 정상 |
| 웹 앱 주소를 열면 구글 로그인 화면 | 액세스 권한이 "모든 사용자"가 아님 → 배포 관리에서 수정 → 새 버전 |
| 학교 Workspace 계정에서 "모든 사용자" 선택지가 없음 | 학교 관리자가 외부 공개 배포를 막아 둔 것. 전산 부서에 문의하거나 (C) 공용 Gmail 계정 사용 |
| 시트에 줄이 안 생김 | `집계!B1` 이 `마감`인지, 같은 이메일+같은 참석 구분 중복인지, Apps Script 편집기 **실행 기록**의 오류 |
| 참가자 명단이 안 보임 | 명단 게시 동의 여부, `상태` 열 `취소` 여부, 1분 캐시 |

그 밖의 항목은 `references/registration-sheet.md` 의 "문제 해결" 표를 보세요.

## 확인한 것 / 확인하지 못한 것

- 확인함(구글 공식 문서): Apps Script 웹 앱 배포 절차와 "다음 사용자로 실행", 새 버전 배포 시 주소 유지.
- 확인하지 못함: 서울대학교가 구성원에게 어떤 구글 계정을 제공하는지, 그 계정에서 외부 공개 웹 앱 배포가 허용되는지, 소유권 이전 후 기존 배포의 동작, 구글 계정 생성 화면의 현재 문구. 실제로 해 보면서 다른 점이 있으면 이 문서를 고쳐 주세요.
