# 보안·개인정보 점검표 — 공개 저장소로 운영할 때

> 이 템플릿으로 만든 홈페이지는 **공개 저장소 + 정적 파일 + 구글 Apps Script** 구조입니다.
> 무엇이 공개되고 무엇이 비공개인지, 어디까지 막아 두었고 어디부터는 운영자가 지켜야 하는지를 정리했습니다.
> "확인함"은 코드와 자동 시험으로 확인한 것, "운영자 책임"은 사람이 지켜야 하는 것입니다.

## 1. 무엇이 공개되나

| 공개됨 (누구나 봄) | 비공개 (권한 있는 사람만) |
|---|---|
| 홈페이지 저장소의 모든 파일: `index.html`, `conference.json`, `assets/`(사진·PDF) | 구글 시트의 등록 응답(이름·소속·이메일) |
| `conference.json` 에 적은 모든 글: 위원 이름·소속, 발표자 정보, 참가자 명단(이름·소속) | Apps Script 코드와 설정(배포 주소만 공개됨) |
| 난독화된 이메일(`email_enc`) — 되돌릴 수 있는 값임 | 스킬 저장소의 `sites/<slug>/conference.json` 원본(비공개 저장소에 둘 때) |
| 등록 접수 주소(`registration.endpoint`) | |
| 저장소의 변경 이력(과거에 올렸다가 지운 파일 포함) | |

**과거 이력도 공개됩니다.** 평문 이메일이나 명단을 한 번이라도 커밋한 저장소를 공개로 바꾸면 지운 뒤에도 이력에서 볼 수 있습니다. 그런 저장소는 공개로 바꾸지 말고, 깨끗한 파일만으로 **새 저장소**를 만드세요.

## 2. 공개 저장소에 절대 넣지 않을 것

- 참석자·발표자의 **이메일 평문, 전화번호, 식사·숙박 정보, 계좌**
- 등록 응답 시트의 내려받은 파일(CSV·XLSX), 명단 파일
- 구글 시트의 공유 링크(편집 가능 링크는 물론 보기 링크도)
- 비밀번호, API 키, 토큰 (이 템플릿은 어떤 비밀값도 필요로 하지 않습니다 — 요구하는 안내가 있으면 의심하세요)
- 사용 권한이 없는 기관 로고·사진 (3절)

`build.py` 는 공개본에 이메일 모양 글자가 남으면 경고를 내고(`WARN 공개본에 이메일 주소가 글자로 포함`), `_`로 시작하는 내부 메모(`_todo`)를 제거합니다. 안내문·소개글 안에 주소를 글자로 적으면 보호되지 않으니 문의처는 `contact` 항목으로 넣습니다.

## 3. 로고·사진·상표

- 이 템플릿은 **어떤 기관의 로고도 포함하지 않습니다.** 서울대학교 공식 엠블럼은 등록 상표이며, 학교 UI 안내 페이지는 구성원이 교육·행정 목적으로 쓰되 외부 사용은 사전 승인을 받도록 안내하고 있습니다(2026-10 확인). 단과대학 로고도 각 대학의 규정을 따릅니다.
- `logo.src` 에는 **사용 권한을 확인한 파일**만 넣습니다. 공개 저장소에 올리는 순간 누구나 내려받을 수 있으므로, 고해상도 원본 대신 홈페이지 표시용 크기(높이 100px 내외)로 줄인 파일을 씁니다.
- 대표 사진(`hero.image`)·단체사진도 촬영자 동의, 피촬영자 동의(얼굴이 크게 나오는 경우)를 확인합니다.

## 4. 이메일 보호의 한계

- 방식: 주소를 뒤집어 slug 로 XOR 한 뒤 base64 로 적고(`v1:…`), 방문자가 그림 속 숫자를 맞히면 브라우저에서 되돌립니다.
- 막는 것: 페이지 소스·저장소 파일에서 `xxx@yyy` 모양을 긁어 가는 자동 수집기.
- 못 막는 것: `app.js` 를 읽고 되돌리는 사람. 따라서 "비밀"이 아니라 "수집 방지" 수준입니다. 본인 동의 없이 게시해도 된다는 뜻이 아니며, 게시 전 본인 동의를 받으세요.
- 확인 코드 그림은 브라우저 안에서만 만들어지고 서버로 전송되지 않습니다(확인함).

## 5. 등록 접수 주소가 공개되는 점

접수 주소(`…/exec`)는 홈페이지 파일에 그대로 들어가므로 누구나 요청을 보낼 수 있습니다. 서버(Apps Script)에 둔 방어:

| 장치 | 내용 | 상태 |
|---|---|---|
| 허니팟 | 사람에게는 보이지 않는 입력칸이 채워져 오면 거부 | 확인함(모의 시험) |
| 최소 경과 시간 | 양식이 열린 뒤 1.5초 안에 제출되면 거부 | 확인함 |
| 길이 제한 | 성명 60자, 소속 100자, 이메일 100자 | 확인함 |
| 수식 주입 방지 | 값 앞의 `= + - @` 제거, 셀 서식을 일반 텍스트로 | 확인함 |
| 중복 제한 | 같은 이메일+같은 참석 구분은 한 번만 | 확인함 |
| 접수 상한 | 기본 3000줄 이후 거부 (`CONFIG.maxRows`) | 확인함 |
| 마감 스위치 | `집계!B1` = `마감` 이면 즉시 중단; `deadline` 이 지나면 자동 마감 | 확인함 |
| 동시성 | LockService 로 동시에 쓰기 충돌 방지 | 코드 확인, 실환경 미확인 |
| 명단 응답 | 동의자의 이름·소속만 반환, 이메일 미반환, 60초 캐시 | 확인함 |

막지 못하는 것: 사람이 손으로 거짓 등록을 여러 번 하는 것, 대량 자동 요청으로 구글 할당량을 소진시키는 것(구글이 차단하거나 접수가 잠시 멈출 수 있음). **운영자 책임**: 시트를 주기적으로 보고 의심 줄은 `취소` 처리, 마감 뒤에는 `B1` 을 `마감` 으로.

## 6. 홈페이지 코드의 안전성

- 모든 글자는 `textContent` 로 넣습니다(HTML 로 해석하지 않음). `conference.json` 에 `<script>` 를 적어도 글자로 보입니다. `innerHTML` 은 내부 SVG 아이콘에만 씁니다(확인함).
- 테마 값(`theme`)은 변수 이름 `--소문자-하이픈`, 값은 색·글꼴·px 문자열만 허용하고 `;` `{` `}` `<` `url(` 은 거부합니다 — CSS/HTML 주입 방지(확인함, `scripts/themes.py` 와 `app.js` 같은 규칙).
- 외부에서 불러오는 것: Google Fonts(글꼴), KaTeX(수식이 있을 때만, jsdelivr CDN), OpenStreetMap(좌표를 넣었을 때만 지도 iframe), Google Apps Script(등록 양식). 방문자의 접속 정보가 이들 서비스에 전달될 수 있으므로 개인정보 처리방침이 필요한 기관이라면 이 점을 적습니다. Google Fonts 를 피하려면 `template/index.template.html` 의 `<link>` 두 줄을 지우면 시스템 글꼴로 표시됩니다.
- 방문자 추적(통계) 코드는 들어 있지 않습니다.
- `conference.json` 을 고칠 수 있는 사람 = 저장소에 쓰기 권한이 있는 사람입니다. 권한을 최소로 주고(Write), 설정 변경(Admin/Owner)은 2~3명으로 제한합니다.

## 7. 계정 보안

- GitHub: 2단계 인증, 조직 Owner 2명 이상, 떠나는 사람 즉시 제거. 저장소에 **Personal access token** 을 넣지 않습니다.
- 구글: 공용 계정에 2단계 인증·백업 코드, 복구 수단을 부서 공용으로. 시트 공유 최소화, "웹에 게시" 금지. → `docs/manual-google-sheet.md`
- AI 도우미에게 비밀번호·토큰을 붙여 넣지 않습니다. 이 템플릿의 어떤 절차도 그것을 요구하지 않습니다.

## 8. 공개 전 점검표 (스킬 저장소를 공개로 바꾸기 전)

- [ ] `sites/` 아래에 **실제 행사 폴더가 없다** (예시 `example-2027` 만 있고, 실명·평문 이메일이 없다)
- [ ] `git log` 전체 이력에 평문 이메일·명단·실제 접수 주소가 없다. 있으면 새 저장소로 옮긴다
- [ ] `references/`, `docs/` 의 예시 주소가 가짜(`AKfy...`, `example.org`)다
- [ ] `LICENSE` 가 있고 README 에 저작권·면책이 있다
- [ ] `python3 scripts/selftest.py` 가 통과한다
- [ ] 로고·사진 파일에 권한 미확인 자료가 없다

## 9. 사고가 났을 때

| 상황 | 조치 |
|---|---|
| 공개 저장소에 평문 이메일·명단을 올림 | 즉시 파일 수정·삭제 커밋 → 그래도 이력에 남으므로 **새 저장소**를 만들어 깨끗한 파일만 올리고 Pages 를 그쪽으로 옮김 → 당사자·기관 개인정보 담당 부서에 알림 |
| 시트를 실수로 공유·웹 게시 | 공유 해제, "웹에 게시" 중지 → 접근 기록(드라이브 활동) 확인 → 기관 담당 부서 보고 |
| 접수 주소로 스팸이 몰림 | `집계!B1` 을 `마감` → 시트 정리 → 필요하면 새 배포(주소 변경) 후 `conference.json` 갱신 |
| 구글 계정 분실 | 복구 수단으로 복구. 불가능하면 새 계정에 새 시트·배포를 만들고 주소 교체(`docs/manual-google-sheet.md` 6절) |

## 10. 이 점검에서 확인하지 못한 것

- 학교 네트워크·보안 정책이 `script.google.com`, `cdn.jsdelivr.net`, `fonts.googleapis.com` 접속을 막는지
- 구글 Apps Script 의 일일 할당량과 실제 대량 요청 시 동작
- 서울대학교의 개인정보 처리 규정상 구글 시트 사용이 "국외 이전·위탁 고지" 대상인지 (기관 담당 부서 확인 필요; 이 저장소는 법률 자문을 제공하지 않습니다)
